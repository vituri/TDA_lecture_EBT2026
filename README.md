## Interactive Quarto presentation

The main presentation is now [`slides.qmd`](slides.qmd), rendered as a
Reveal.js deck. It is a redesign of the talk rather than a line-for-line port of
the Typst version: explanations use fragments, the Reeb construction has a live

```sh
quarto preview
```

opens the deck with live reload. For the presentation build:

```sh
quarto render
```

Then open `docs/index.html`. The build embeds Reveal.js, the theme, math
rendering, interactions, and the selected Julia figures into that HTML file. The
figures are also copied beside it under `docs/figures/` for inspection.
The single HTML file works offline; copying the whole `docs/` directory
is still the safest handoff.

## Figures

Every graph in the deck is real TDAmapper.jl output. The rotating torus and
flamingo point clouds are also generated from the exact samples used by their
Mapper panels. Nothing is hand-drawn except the schematics that illustrate
*definitions* (the Reeb torus, the pipeline diagram, the nerve triangle, the
tent for the gradient picture).

```sh
julia --project=. scripts/make_figures.jl
julia --project=. scripts/make_filter_figures.jl
julia --project=. scripts/make_differentiable_figures.jl
```

These write `figures/*.png`, `figures/*.gif`, and the corresponding stats files.
`stats.txt` holds the football numbers quoted on slides; `flamingo_stats.txt`
records the fixed sample and the four filter comparisons;
`differentiable_stats.txt` records the rotated-table and learned-football
benchmarks. If you change a parameter, re-run the relevant script and re-check
the captions against its stats file — the deck asserts these numbers.

The differentiable generator contains two label-free optimizations. A synthetic
table is embedded isometrically from three into ten dimensions: PC1 follows the
tabletop, while a normalized linear filter trained on a branch-weighted
persistence objective recovers the hidden normal. The second experiment starts
from the football PC1 lens and learns a standardized linear combination of all
18 features. Position labels are joined only afterward, so the script reports
both the optimized topological score and held-out purity rather than treating
the training objective as semantic validation.

The flamingo comes from the
[`mapperGUI` example cloud](https://github.com/vituri/mapperGUI/tree/master/examples)
(26,907 points). The script
downloads it only when needed and stores a deterministic 2,400-point farthest-point
sample—built by `MetricSpaces.farthest_points_sample_ids`—in
`data/flamingo_sample.csv`; all four Mapper graphs use that same sample, cover,
and DBSCAN parameters so the filter is the only changing variable. The geodesic
filter is eccentricity computed with all-pairs shortest-path distance on a
connected 3-nearest-neighbour graph with Euclidean edge weights. Its Mapper also
uses this distance matrix for DBSCAN, since an intrinsic filter with ambient
Euclidean clustering can still glue the feet. The generator geometrically
separates the two feet and asserts both that no graph edge crosses directly
between them and that no Mapper node contains points from both feet; its GIF
also draws all graph edges. This adapts
the [`mapperGUI` graph-walk visual](https://github.com/vituri/mapperGUI/blob/master/pics/geodesic-example.png):
the original R app builds a relative-neighbourhood graph, while this deck uses
the requested k-NN graph explicitly.

The soccer data is built by the workshop's builder
(`../TDA_workshop_EBT2026/scripts/build_soccer_data.jl`), which caches to
`../TDA_workshop_EBT2026/data/processed/soccer_mapper_input.csv`. Pass
`build_soccer_data(force=true)` to rebuild.

### Why `mapper_draw.jl` exists

`TDAplots.mapper_plot` is what the code slides show and what the torus figure
uses. The football figures need three things it does not expose, all of them
rendering-only — no Mapper object is built any way other than through the public
API:

- **Ordered categories.** `mapper_plot`'s string branch groups labels with `sort`,
  so Defender / Forward / Midfielder comes out alphabetical, scrambling the one
  axis the football graph is about.
- **Player labels**, with leader lines so a name in a dense graph is attached to a
  specific node.
- **Component packing.** A force-directed layout has nothing to push
  *disconnected* pieces anywhere in particular, so a graph with a dozen singletons
  spends most of its canvas on whitespace. `layout_packed` lays each component out
  separately and shelf-packs the results.

The first two would be reasonable additions to TDAplots (`node_labels=`, and an
ordered-palette option); they are kept local here so that preparing a talk does
not change a published API.

## Claims that are machine-checked

`verify_layering.jl` asserts the structural claim on the *Two lenses* and
*overlap* slides, so it cannot go stale:

With a 1-D filter, every node is a cluster inside one slice, and clusters within a
slice are disjoint — that is structural rather than per-refiner, since
`Refiners.refine_cover` asks for one label per point and then forms
`ids[findall(==(cl), labels)]`. `Uniform` spaces interval centres one step apart
with radius `(step/2)(1 + expansion)`, so slices *i* and *i+2* meet exactly when
`expansion > 1`. Below that, `node ↦ its slice` is a graph homomorphism onto a
path, so the Mapper graph is **bipartite and triangle-free**. A 2-D grid cover has
cell *(i,j)* meeting *(i+1,j+1)*, so the target is the **king graph** on ℤ², which
has triangles.

Measured on the football data: 0 triangles at expansion 0.2 / 0.4 / 0.8 for
DBSCAN, `FirstEmptyBin` **and** `Trivial`; 43 triangles at 1.2; 322 for the
12×12 two-lens graph. `expansion = 1` is the boundary — slices *i* and *i+2* then
share a single endpoint — and is deliberately not asserted; the slides say
`expansion < 1`.

The nerve comparison holds all 146 two-lens clusters and their node positions
fixed. It then changes only the edge predicate: ordinary nonempty intersection,
at least two shared players, at least 20% of either cluster, or Jaccard similarity
at least 0.1. The slide explicitly notes that thresholded variants are not the
ordinary topological nerve, so the nerve lemma does not automatically apply to
them.

## Known caveats, deliberately

- **Season is 2020–21.** The FBref mirror's newest complete season. The slide
  states the season explicitly so it reads as a historical snapshot, not stale
  data. Refresh the mirror and re-run `make_figures.jl` to update.
- **Dominant position is a tie in 3 of the main graph's 22 nodes.** Said on the
  slide rather than hidden. `node_colors`' default mode function would instead
  join ties into labels like "Defender/Midfielder", which are not categories —
  `position_group` has exactly three values. `dominant_position` breaks ties
  toward the more defensive role and counts them.
- **Eccentricity produces flares by construction.** The *Where the flares come
  from* slide says so; the shape is partly authored by the lens, so it is weaker
  evidence than the same structure under a filter chosen for meaning.
- **`dens` purity (0.927) is not comparable** to the other filters' — it is
  inflated by 8 isolated singletons, which are trivially pure. The filter-zoo
  slide compares edges / components / max node size instead.
- **One residual mojibake:** `José Luis Gayà` — the source bytes are truncated,
  so `fix_mojibake` correctly declines to emit invalid UTF-8. Not a player named
  on any slide.
- **Two generated figures are unused**, kept as options: `soccer_pca.png`, the PCA
  scatter of the same players, if you would rather make the "why not a scatter?"
  contrast on real data than on a published figure; and
  `soccer_2lens_plain.png`, the two-lens graph without labels, sized for a
  side-by-side against the one-filter graph.
- **One placeholder** remains in the deck, on *The shape of data*: a slot for
  Alagappan's NBA Mapper figure (MIT Sloan 2012) or the Lum et al. 2013 graph.
  The two-lens construction is *not* attributed to either — Ayasdi's workflow used
  multiple lenses, but no specific lens pair is claimed here.

## Timing

The expanded interactive deck is 40 slides, or roughly 75–80 minutes at two
minutes per slide. For a 60-minute version, move quickly through the four
flamingo filters and treat the clustering, nerve-rule, and Ball Mapper definition
slides as one-minute setup slides. For a 30-minute version, keep one flamingo
filter, the football filter comparison, the two-lens result, and one slide each
for clustering, nerve choice, and Ball Mapper; omit the parameter-sensitivity
and application-detail sequences.
